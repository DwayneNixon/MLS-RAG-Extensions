## Recorded same-node comparison (13 November, damnii12 RTX 2080 Ti)

The job `3716786` tested all compared configurations on one RTX 2080 Ti and recorded the exact environment at `extensions/results/gemm_blocks_3716786/00_environment.txt`.

| Configuration | Mean ASR latency (ms) | Task 3 test |
|---|---:|---|
| PyTorch reference before / after | 769.8 / 785.0 | Independent reference |
| Original v1 task GEMM, all CUDA | 2741.6 ± 8.7 | 10/10 PASS |
| v2 TM4/TN4/BN64/BK16, all CUDA | 1593.2 ± 0.6 | 10/10 PASS |
| **Selected v2 TM4/TN4/BN64/BK32, all CUDA** | **1481.9 ± 2.1** | **10/10 PASS** |

The selected BK=32 configuration is **~1.85× faster** than the original custom-CUDA GEMM version in this job (2741.6/1481.9), with ~46.0% lower end-to-end latency; it is ~7.0% faster than the BK=16 configuration measured in the same sweep. It remains about **1.9× slower than the PyTorch reference** on this sample, and peak reported PyTorch-allocated memory was **8.56 GiB** vs **8.88 GiB** for PyTorch in these recorded runs. No claim is made that this is a universal optimum or that the difference between variants has a statistical confidence interval across independent GPU sessions.

**Correctness:** `extensions/results/gemm_blocks_3716786/test_tm4_tn4_bn64_bk32.txt` verifies all 10 GEMM shapes. `extensions/results/gemm_blocks_3716786/e2e_tm4_tn4_bn64_bk32.txt` verifies the expected transcription, 13 tokens and 100% coursework sample check. `extensions/results/v2_dispatch_racecheck.txt` has 0 racecheck hazards for the **BK=16** ancestor; **BK=32 has not been independently racechecked** in these saved results. The full historical 33/33 check in `results/final_test.txt` belongs to the **original v1** `csrc/` snapshot, not this promoted candidate.

## Remaining required final validation

To make the promoted standard-path code submission-ready, run **all of the following on one RTX 2080 Ti node in a clean checkout of the submission draft**. Preserve actual outputs and do not copy the previous v1 full-suite log as if it covered BK=32.

From the DICE login/head node, using a checkout or cloned copy of this branch (do not reset or overwrite the existing university working tree):

```bash
srun -p Teaching --gres=gpu:nvidia_geforce_rtx_2080_ti:1 \
  --cpus-per-task=2 --mem=16G --time=01:00:00 --pty bash
```

Then, inside the GPU shell, with the correct working directory and `mls-asr` environment activated:

```bash
export PATH=/opt/cuda-12.8.0/bin:$PATH
conda activate mls-asr
cd ~/MLS-RAG-Extensions/hw1-asr   # adapt if your clean branch checkout uses a different path
nvidia-smi -L | tee results/submission_gpu.log
make clean
set -o pipefail
make test 2>&1 | tee results/submission_make_test.log
./run.sh --profile 2>&1 | tee results/submission_profile.log
compute-sanitizer --tool racecheck build/sm_75/test_task3_gemm small \
  2>&1 | tee results/submission_racecheck.log
```

Look for **all four official task groups passing** (4+11+10+8=33 cases), a **PASS** transcription, correct all-custom CUDA backend and RTX 2080 Ti GPU name. The final checkpoint should include matching GPU/node identity and the final five-file commit SHA. The profiling result is measured, not assumed to equal the historical 1481.9 ms.

**Note:** `./run.sh --profile` invokes `make -s lib` itself; it expects the usual default library build. If the university shared filesystem makes linking unreliable, use a clean `BUILD=/tmp/...` path with the existing runner's `ASR_LIB` support and document this divergence before claiming literal `./run.sh --profile` reproduction.
